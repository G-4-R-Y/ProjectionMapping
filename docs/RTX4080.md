# RTX 4080 workflow

This guide applies to **Windows or Linux systems with an NVIDIA RTX 4080**. Treat diffusion as an asynchronous semantic renderer, not necessarily the 60 FPS display loop.

Recommended architecture:

1. Camera at 720p/1080p with manual exposure once calibrating.
2. Perception at camera rate: mask/flow/depth as needed.
3. Diffusion around 768x432 or 960x540 initially, FP16/TensorRT where supported.
4. Keep only the newest camera frame if inference falls behind; never queue stale frames.
5. Realtime graphics/compositing runs the final display-rate motion, feedback, particles, warps and upscaling.
6. On Windows, Spout can move frames locally into TouchDesigner/MadMapper without video encoding. On Linux, use direct fullscreen today while additional transport backends are developed.
7. MadMapper/TouchDesigner remain optional final spatial/compositor layers; the calibration code here can eventually replace more of that workflow.

The repo includes `LatestFrameWorker` and `experiments/04_streamdiffusion_live.py` implementing the bounded latest-frame async inference pattern.

## StreamDiffusion environment

Use Python 3.10 or another version validated by the selected StreamDiffusion/CUDA stack, plus a recent NVIDIA driver. The Daydream StreamDiffusion fork currently documents PyTorch >= 2.2 and supports xformers and TensorRT acceleration paths.

### Create the environment

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[dev,vision,ml]"
```

Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -e '.[dev,vision,ml]'
```

Install PyTorch with the CUDA wheel appropriate to the local driver/runtime rather than blindly pinning a wheel from this repository.

Then install the current StreamDiffusion fork using modern PEP 508 direct-URL syntax:

```text
python -m pip install "streamdiffusion[tensorrt,controlnet,ipadapter] @ git+https://github.com/daydreamlive/StreamDiffusion.git@main"
```

Recent pip versions reject the older form with extras inside an `#egg=` fragment, for example:

```text
# OLD / DO NOT USE
python -m pip install "git+https://github.com/daydreamlive/StreamDiffusion.git@main#egg=streamdiffusion[tensorrt,controlnet,ipadapter]"
```

That old form can fail with `error: invalid-egg-fragment`. If installation fails, stop there: `python -m streamdiffusion.tools.install-tensorrt` cannot work until the `streamdiffusion` package has actually been installed.

Verify the base package before installing TensorRT:

```text
python -c "import streamdiffusion; print('StreamDiffusion import OK')"
```

For TensorRT, upstream currently provides:

```text
python -m streamdiffusion.tools.install-tensorrt
```

Start with `xformers` first so correctness is separated from TensorRT engine-build issues.

## Live baseline

The same command works in PowerShell, cmd, bash, and zsh when written on one line:

```text
python experiments/04_streamdiffusion_live.py --camera 0 --display 1 --width 768 --height 432 --acceleration xformers
```

Press `Esc` to exit. Every ~2 seconds the process prints display FPS, inference FPS, last/EMA inference time, submitted frames, processed frames, dropped stale frames, and inference errors.

### Windows Spout output

For local Spout output instead of fullscreen projection:

```text
python experiments/04_streamdiffusion_live.py --camera 0 --width 768 --height 432 --acceleration xformers --spout --sender ProjectionMapping
```

Receive the `ProjectionMapping` sender in TouchDesigner. The current Python Spout adapter is a bring-up path; the M2 roadmap goal remains validating a truly shared GPU texture path with no avoidable CPU readback.

### Linux output

Do not pass `--spout`. Use fullscreen output today. A Linux-native shared-texture/network path is tracked separately in the platform roadmap.

## Benchmark progression

Run the same camera/scene/prompt while changing one variable at a time:

1. `512x512`, xformers
2. `768x432`, xformers
3. `960x540`, xformers
4. TensorRT at the best interactive resolution
5. compare `stabilityai/sd-turbo` against LCM-based models
6. try one-step vs multi-step/t-index schedules
7. add similarity filtering for static/low-motion scenes
8. add TemporalNet / StreamV2V only after baseline latency and flicker are recorded

The important measurement is not only maximum model FPS. Record frame age and motion-to-photon latency. A 20 FPS semantic renderer can still drive a smooth 60 FPS installation when the procedural/display path is decoupled; stale queued frames cannot.

## Measurements worth logging

- OS + kernel/build
- NVIDIA driver
- CUDA runtime
- PyTorch / StreamDiffusion revision
- camera exposure + capture latency
- perception latency
- diffusion latency (p50 / p95 / p99)
- stale-frame drop rate / queue age
- GPU memory usage
- compositing latency
- transport latency and copy count
- projector input-to-photon latency
- total motion-to-photon latency
- camera-observed registration error versus target velocity

Do not optimize inference FPS in isolation. For moving geometry, end-to-end latency, newest-frame age, registration, and temporal stability matter more.
