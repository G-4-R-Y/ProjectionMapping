# Weekly research sweep — 2026-09-15

Window: roughly 2026-09-08 through 2026-09-15. This note intentionally avoids repeating candidates already covered in `2026-09-14.md` unless there was a meaningful new development.

## Summary

This was a stronger week for shader/WebGPU infrastructure than for directly deployable realtime video-diffusion systems. The most useful fresh signals are Vercel Labs' `vgpu`, the newly launched OpenShaders catalog/editor effort, and continued multi-language/WGSL work in LYGIA. None is a good core dependency for the current Python/OpenCV/CUDA runtime yet, so this sweep does not vendor external code or claim hardware validation.

## 1. vgpu — WebGPU runtime worth watching

Repository: https://github.com/vercel-labs/vgpu

**Status:** high-value architecture reference; defer integration.

**License:** MIT.

**Freshness:** actively pushed through 2026-09-14.

`vgpu` is a typed, modular WebGPU library spanning fullscreen effects, scenes, GPU tensors and neural-network/math workloads. Particularly relevant to ProjectionMapping are typed WGSL imports/reflection, explicit frame/pass construction, headless Node via Dawn, and a deterministic mock backend intended for tests/CI.

**Why it matters:** this is a credible future route for a browser/native-WebGPU shader renderer with testable shader pipelines rather than ad-hoc GLSL strings. It also fits the long-term goal of keeping high-rate deterministic rendering independent from slower neural inference.

**Why deferred:** adopting it means adding a TypeScript/Node/WebGPU runtime beside the existing Python renderer. That is architectural, not a small weekly integration. Revisit when the project adds a dedicated GPU shader backend or web control/render surface.

## 2. OpenShaders — newly launched shader ecosystem

Repository: https://github.com/openshaders/openshaders

**Status:** watch; do not ingest creator shaders automatically.

**License:** platform repository MIT; individual creator shaders are expected to choose their own licenses.

**Freshness:** repository created 2026-09-06 and pushed 2026-09-09.

The project is building a WebGL/WebGPU shader collection, live editor, reusable React/JavaScript modules and a registry-style installation workflow. The repository itself currently describes the platform as in development rather than exposing a mature shader library suitable for direct consumption.

**Why it matters:** it could become a useful discovery source for visually polished shader effects and a model for a shader/preset registry in ProjectionMapping.

**Why deferred:** source/catalog maturity is still early, and the platform license does not automatically license creator shaders. Any future import must preserve per-shader provenance and license metadata.

## 3. LYGIA — active WGSL / multi-language shader infrastructure

Repository: https://github.com/patriciogonzalezvivo/lygia

**Status:** strong shader-library reference; no vendoring this sweep.

**Freshness:** commits on 2026-09-08 fixed WGSL gnoise guards; 2026-09-14 added a more efficient C++ bundle path.

LYGIA remains unusually relevant because the same granular shader vocabulary targets GLSL, HLSL, Metal, WGSL/WESL and CUDA. That aligns with our cross-platform ambitions and future GLSL/SDF Cyber Mage work.

**Why deferred:** GitHub reports a non-standard/no-assertion license rather than a simple permissive SPDX license. More importantly, ProjectionMapping still lacks a first-class shader backend, so copying shader modules now would create an orphan integration. Use it as a design/reference source until those two constraints are resolved.

## 4. three-projection-mapper — active browser mapping library

Repository: https://github.com/bhoffmann93/three-projection-mapper

**Status:** watch as mapping-UX/math reference; defer integration.

**Freshness:** pushed 2026-09-09.

A Three.js projection-mapping library covering perspective warping and mapping-oriented transforms. It is directly adjacent to the project's mapping goals and potentially useful as a browser-side preview/editor reference.

**Why deferred:** GitHub reports a non-standard/no-assertion license, and introducing a Three.js runtime is not justified while the existing Python calibration/mapping path is still awaiting real projector-camera validation.

## Integration decision

No external project met all of the weekly auto-integration criteria simultaneously: fresh, clearly licensed at the component level, small enough in scope, compatible with the existing Python runtime, and useful without introducing a parallel rendering stack. The correct action this week is therefore research capture rather than dependency growth.

The implementation priority remains internal and already represented in the roadmap: finish the deterministic Cyber Mage shader/effect abstraction, add real pose/hands, benchmark Neural Mirror temporal stabilization, and validate projector-camera calibration on hardware. A future WebGPU backend should explicitly evaluate `vgpu`; a future shader registry should evaluate OpenShaders while enforcing per-asset license/provenance metadata.
