## Promoted small integration: Varda external launcher

- **Upstream:** [im-knots/varda](https://github.com/im-knots/varda); [v0.10.0 release](https://github.com/im-knots/varda/releases/tag/v0.10.0), published **2026-11-08**; MIT. v0.9.0 was released 2026-10-26. The v0.10.0 notes include loopback output audio, performance and macOS startup fixes, revised Aurora and compute-shader effects.
- **Why:** Existing portable native Rust/Vulkan VJ mapper with routing (Sources → Decks → Channels → Surfaces → Outputs), GLSL 450/ISF-like shaders, optional OSC and native/shared-video capability. Useful to test an actual external compositor/mapper without making TouchDesigner mandatory, and to compare the studio's visual polish against a shipping alternative.
- **Maturity:** public source, tagged release and downloadable Windows x64 ZIP, macOS universal DMG, Linux x86_64 AppImage/Flatpak. Portable launch contract is based on documented CLI: --scene, --stage, --shader-dir, --no-osc, --no-ndi.
- **Integration scope:** optional config fragment `configs/features.d/varda_external.toml` in the existing Textual registry; no dependency added, no binary downloaded, no fork, no transport bridge, no conversion of our GLSL shaders. If the executable is missing the UI reports the PATH prerequisite. Tested only as a manifest/argv/dependency-gate contract, **not** as a running Varda instance.
- **OS and hardware:** Windows x64, Linux x86_64, macOS Intel/Apple Silicon packages listed by upstream; Vulkan/graphics-driver compatibility and desktop/GPU capture capabilities require testing. NDI separately needs its proprietary runtime/SDK; Windows Spout and macOS Syphon remain upstream-specific features, **not implemented inside ProjectionMapping**. For macOS use upstream's documented package and graphics API, not a CUDA assumption.
- **Milestones:** M2 external interoperability, M7 audiovisual comparison, M9 mapping/show-control reference. Next hardware test: actual installed launcher → open scene → window lifecycle/ESC/focus → route output to intended display → measure p50/p95 frame-time/transport copies, preserve control-deck state, confirm no unexpected network exposure. A local executable may need a PATH wrapper depending on package type.
- **Security:** Varda is a separate process. Do not automatically start its headless HTTP API or expose OSC/NDI services to a network. Review its networking configuration and downloaded binary provenance before a show.

## Relevant comparators and carryover findings — *not claimed new this month*

- [Visionary](https://github.com/Visionary-Laboratory/visionary) (Apache-2.0): WebGPU/ONNX live 3D/4D Gaussians and neural avatars; substantial adjacent research for **Spatial Memories** and M10. Browser GPU with WebGPU support required (Windows/Linux/macOS browser availability is device/driver-dependent). Current Spatial Studio is WebGL2 with a point cap; adopting Visionary requires a dedicated WebGPU renderer path, explicit data-format/LOD contract, memory metrics, and license audit of supplied model assets. **Not a small integration.**
- [WebSplatter](https://github.com/websplatter/WebSplatter) (MIT, repository last source push observed 2026-08-29): promising WebGPU device-portable 3DGS viewer and PLY-to-glTF tooling, but there is **no verified post-October code update**, so classify as a comparison candidate, not a November discovery. Browser/WebGPU, Node toolchain and asset migration required. **Defer** until a real 3DGS capture exists and Spatial Studio needs it.
- [Ghost Arcade](https://github.com/riskcapital/ghost-arcade) v2.0.13 (released **2026-09-29**): active mapping/VJ competitor with native wgpu, surface warps, show control and optional Spout/Syphon/NDI. Its latest 2.x source is explicitly **not** the default 1.9 branch. AGPL-3.0 makes code reuse/combining a separate compliance decision. Windows/macOS desktop, Linux browser-only path indicated by upstream. **Do not vendor**; compare external results, rig throughput, and artist workflow (M2/M7/M9).
- [Blender TextureSharing](https://github.com/maybites/TextureSharing) advertises Windows Spout, macOS Syphon, plus NDI/OMT on Linux/Windows/macOS. Current receive paths carry upstream performance warnings; external NDI binaries have distinct licensing. Release chronology not established for this window. **Transport comparator only**, not proof of zero-copy or compatibility with our OpenGL/CUDA stack.
- [Spout2](https://github.com/leadedge/Spout2) remains the Windows native texture-sharing baseline (BSD-style SDK); the actual **Spout to consumer** round trip on an RTX 4080 must still be benchmarked. Syphon is a separate macOS path; NDI/OMT are network/video transports and should not be called zero-copy interchange with CUDA.

## Updated priority and acceptance measurements

1. **M1/M5 first:** capture a real projector/camera calibration bundle, inverse maps, hole/occlusion/confidence masks, gamma/color and reprojection QA. VAComp is a **future viewer-aware approach**, not a substitute for getting ground truth now.
2. **M2/M7:** compare direct fullscreen, real Windows Spout, and optionally installed Varda as an *external compositor*. Measure time-to-first-frame, frames dropped, p50/p95/p99 scanout latency and CPU readbacks; explicitly log OS, GPU, driver, projector, refresh and resolution.
3. **Spatial Memories/M10:** first verify WebGL2 point-cloud black-floor, LOD, clipboard upload and real PLY geometry on projector; keep WebGPU/3DGS in a separate experiment until actual scan assets and target browser GPU support exist.
4. **M3/M4:** use deterministic point/room geometry and optical-flow keyframe baseline as judge; EdenLive becomes eligible only with compatible model licenses, isolation, VRAM profile and measured quality gain on actual hardware.
