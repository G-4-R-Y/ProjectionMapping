# Projection Mapping Research Sweep — 2026-10-14

**Review window:** 2026-09-16 to 2026-10-14. Earlier findings: [2026-09-14](2026-09-14.md), [2026-09-15](2026-09-15-weekly.md). Inspected `main` at `8a5fdc2ff` (2026-09-27): AGENTS, MEMORY, ROADMAP, feature tracks, source and tests, plus CI configuration.

**Summary:** The most relevant advance is NVIDIA's separation of deterministic spatial state from streaming neural rendering, which closely mirrors M4/M6. New Gaussian-splat pipelines and mature VJ applications are useful external references, but none clears all automatic integration gates. **Research/documentation only; no new dependency or functionality is claimed.**

## Verified new or materially changed work

### 1. NVIDIA StreamRender-H3 — highest technical relevance

- Sources: [NVIDIA project](https://nvlabs.github.io/Sana/Sol-Engine/StreamRender-H3/), [RAVEN news dated 2026-10-12](https://github.com/mvp-ai-lab/RAVEN), [Sol Engine repo](https://github.com/NVlabs/Sana).
- **Why:** A deterministic simulator owns geometry, physics and segmentation; a history/reference-conditioned streaming diffusion renderer supplies appearances. This is a direct M3/M4/M6 architecture precedent for generated room materials with unchanged spatial state.
- **Maturity:** research demonstration tied to a racing game, not a drop-in general-room projector renderer; no reproducible consumer-GPU turnkey integration verified.
- **Hardware/OS:** paper/demo reports a 218 ms diffusion step on **8 NVIDIA GB200 GPUs**, not end-to-end capture-to-projector latency, not RTX 4050/4080. Datacenter NVIDIA/Linux-class stack; Windows and macOS not verified.
- **Decision:** experiment conceptually with a typed SemanticFrame/control-map contract and offline captures; defer neural backend until weights, footprint, terms and single-GPU result are credible.

### 2. Mobile-4DGS and browser renderer — compact moving scenes

- Sources: [Mobile-4DGS](https://github.com/xiaobiaodu/Mobile-4DGS), [browser renderer](https://github.com/xiaobiaodu/mobile-4dgs-project), [paper](https://arxiv.org/abs/2610.05289).
- **Freshness:** created 2026-09-29; upstream announces both code and WebGL renderer on **2026-09-30**, with pushes through Oct 14.
- **Why:** compact static/dynamic Gaussian-splat scene playback could serve M6 semantic-room assets and M9 visualization; keep splat assets export-neutral.
- **Maturity/license:** very new training/reproduction stack; no clear top-level LICENSE or SPDX terms in either repository as inspected. README says its *ideas* may be used commercially; that is **not permission to vendor code**.
- **Hardware/OS:** Python 3.11, CUDA 12.6, GPCC/TMC and RAPIDS cuML training route is Linux/NVIDIA-oriented; Windows unverified, macOS CUDA unsupported. WebGL viewer may work on Windows/Linux/macOS browsers if GPU/WebGL requirements hold, untested.
- **Decision:** licensing-blocked research candidate, no code copied.

### 3. InfiniSplat v2 — offline room reconstruction candidate

- Sources: [InfiniSplat v2](https://github.com/zju3dv/InfiniSplat/tree/main/InfiniSplat_v2), [installation](https://github.com/zju3dv/InfiniSplat/blob/main/InfiniSplat_v2/INSTALL.md), [license](https://github.com/zju3dv/InfiniSplat/blob/main/LICENSE).
- **Freshness:** repo pushed **2026-10-13** with public v2 code, inference commands and weights.
- **Why:** feed-forward reconstruction from 2–32 overlapping room photographs with optional known camera poses. M6/PF4 offline geometry/asset-generation reference, not replacement for projector-camera calibration or real-time performer tracking.
- **Maturity/license:** usable independent CLI and documented weights; **Project Registration License v1.0** requires registration for organizational project use; third-party and checkpoint terms also matter.
- **Hardware/OS:** Python 3.10–3.12 + NVIDIA CUDA; upstream documents a Linux H20 setup (CUDA 12.8/PyTorch 2.7.1). Windows CUDA not validated in documentation; macOS CUDA unsupported. Optional HTML splat viewer is browser-dependent.
- **Decision:** separate/offline evaluation only after explicit license review, never install in portable core.

### 4. Ghost Arcade 2.0.13 — external mapping/VJ comparator

- Source: [Ghost Arcade](https://github.com/riskcapital/ghost-arcade), [2.x development source](https://github.com/riskcapital/ghost-arcade/tree/codex/windows-v2-testing), [2.0.13 notes](https://github.com/riskcapital/ghost-arcade/blob/codex/windows-v2-testing/docs/releases/v2.0.13.md).
- **Freshness:** README refreshed on **2026-09-30** and describes 2.0.13 features: native Rust/wgpu, live VJ decks, mesh/Bezier mapping, shader parameter metadata, stage simulation, MIDI/OSC/Link, mobile companion, platform transport options.
- **Why:** strong independent M2/M7/M11 UX, visual, mapping and GPU-transport baseline for our persistent performance console. Do not mistake upstream assertions for measured local zero-copy performance.
- **Maturity/license:** AGPL-3.0-only application, not a small permissive library. Repository's `main` is still legacy 1.9 source; 2.x source is on development branch, and no GitHub tagged releases were returned during this sweep.
- **OS:** Windows/macOS desktop workflows described; legacy README treats Linux as browser-only, whereas actual native 2.x Linux support is not established. All GPU transport paths require hardware tests.
- **Decision:** keep process-external; compare performance and controls without copying code.

### 5. Consumer structured-light fringe scanner — calibration QA reference

- Source: [MIT-licensed 2026 course prototype](https://github.com/hectorcs23/fringe-projection-3d-reconstruction), created **2026-09-19**.
- **Why:** 4-step fringe phase demodulation, modulation/shadow masks, multi-frequency temporal unwrap, triangulation, and explicit measurement error inspire small deterministic M1/M5 QA fixtures.
- **Maturity:** single educational prototype reports 69.2% valid pixels, 1.75 cm height landmark RMSE and 2.09 cm leave-one-out RMSE; needs a better camera/projector model and is not precise enough to replace our Gray-code/phase calibration.
- **Hardware/OS:** Python vision math broadly portable to Windows/Linux/macOS; camera drivers, mini projector timing and actual accuracy require validation.
- **Decision:** reference/test-design candidate, no runtime integration.

### 6. Blender 5.3 Gaussian splats — external asset authoring

- Source: [official development release notes](https://developer.blender.org/docs/release_notes/5.3/rendering/); splat feature landed **2026-09-16**, release scheduled **2026-11-10**.
- **Why:** PLY/SPZ splat import and point-cloud/Geometry Nodes rendering could make reconstructed scene assets inspectable in an existing desktop DCC (M6/PF4).
- **Maturity:** pre-release on sweep date; missing native splat export and outstanding color/performance caveats.
- **Hardware/OS:** standalone Blender on Windows/Linux/macOS with GPU-feature variance; not runtime portable OpenGL transport.
- **Decision:** re-evaluate stable release; do not vendor Blender.

## Integration gate and non-findings

No new upstream project satisfies **clear applicable license, stable/reproducible implementation, compatible small/medium integration, declared OS/hardware path, and local deterministic testability** simultaneously. Do not add requirements, fork third-party code, or label any visual production-ready. Earlier LiveEdit, LiveLight, OpenVJ, vgpu and rusty-syphon-spout remain from the September ledger without a verified newly compatible release. No newly verified portable zero-copy Spout/Syphon/NDI Python bridge superseded current architecture. GitHub `updated_at` can change with repo metadata; use push/creation dates and explicit release notes, as above.

## Actionable changes to the milestones

- **M1/M5:** record a real structured-light bundle; compare valid pixel/modulation mask against shadow/saturation and report reprojection and inverse-map hole errors, then benchmark the radiometry LUT baseline.
- **M2:** remove GPU-to-CPU readback and measure copy count / motion-to-photon delay separately on Windows Spout, Linux direct GL and macOS future Syphon. Ghost Arcade is only an external comparison.
- **M3/M4/M6:** design a serializable `SemanticFrame` with camera matrices, timestamp, stable object IDs, semantic/depth/mask/edge maps and visual reference metadata. Render deterministic Room Skin at refresh rate and compare *optional* async neural keyframes against identical recorded input under 6 GiB/4080 budgets.
- **M6/PF4:** keep GLB/PLY/SPZ provenance and material import/export independent of reconstruction technology; optional research engines run in isolated processes.

## Audit, tests, and limitations

Existing repository: camera/projector patterns/phase/Gray code, homography and LUT dataset acquisition, Room Skin and optical flow, latest-only StreamDiffusion, ModernGL procedural scenes and GPU particles, performer state and OSC/MIDI controls, Windows Spout diagnostic. **Hardware validation remains pending.** Windows Spout, Linux native fullscreen, and macOS native Syphon are *different* support statuses.

The historical six-job Ubuntu/Windows/macOS × Python 3.10/3.12 test matrix passed in September, but commit [`8a5fdc2ff`](https://github.com/G-4-R-Y/ProjectionMapping/commit/8a5fdc2ff) **removed its Actions workflow on 2026-09-27 for cost control**. The separate `desktop-build.yml` file still exists and is not proof that current tests pass. No new tests or hardware measurements were run in this docs-only update, and no billable CI was triggered. The automation container lacks network access to clone the repo and run `pytest` locally.
