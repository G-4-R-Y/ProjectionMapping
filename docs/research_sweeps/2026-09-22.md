# Research sweep — 2026-09-22

Window: 2026-09-15 through 2026-09-22. The sweep prioritized source-level changes that were actually committed during the window; projects merely re-indexed by search were not counted as new.

## Promoted: Brush

Source: https://github.com/ArthurBrussee/brush

License: Apache-2.0. Upstream is a cross-platform Rust Gaussian-splat reconstruction/viewer stack using WebGPU-compatible compute through Burn. It can load `.ply` / `.compressed.ply`, supports animated splat archives, runs on Windows/macOS/Linux and can build for web/mobile.

Meaningful updates in-window:

- 2026-09-16: training/rendering work reduced GPU launches, moved scan/radix-sort work into shared GPU kernels, removed avoidable readbacks, and improved fusion of training operations.
- 2026-09-20: migrated more custom operations onto Burn-generated Fusion implementations and added a fusion regression test.

Why it matters here: Brush is a strong candidate for the volumetric-content side of M4/M6 without pulling CUDA-only training dependencies into the Python control runtime. Its viewer is immediately useful for inspecting room/performer splats, and its portable compute direction is aligned with the repository's cross-platform goals.

Implemented in this sweep:

- `projection_mapping.external_tools.build_brush_viewer_command`: deterministic, shell-free command construction.
- `experiments/22_brush_splat_viewer.py`: opt-in adapter that launches a user-installed `brush` binary against a local source or URL.
- no automatic download/install, no dependency changes, and no claim of GPU/hardware validation.
- unit coverage checks path preservation and input validation.

The adapter intentionally stays out-of-process. Brush owns a substantial Rust/WebGPU/Burn stack; embedding it in the Python environment would create dependency and lifecycle coupling for little immediate benefit.

Hardware status: **not validated**. The adapter itself is deterministic; actual Brush rendering, WebGPU support, splat throughput and projector suitability require testing on the target machine.

## Deferred: SuperSplat 3.3.1 / experimental viewport warping

Source: https://github.com/playcanvas/supersplat

Relevant upstream change: 2026-09-16 commit `3ab7965` (“Improve stochastic resolve and add experimental viewport warping”), followed by the 3.3.1 version commit on 2026-09-21.

The change is interesting because it combines stochastic splat rendering with a warped projection path and GPU depth reduction. That is adjacent to our spatial-warp and volumetric-rendering roadmap, but the implementation is tightly coupled to PlayCanvas/TypeScript/WebGPU render passes. Copying it into the ModernGL/Python runtime would be the wrong abstraction and could create licensing/maintenance ambiguity.

Action: keep as a design reference for a future native GPU compositor. In particular, evaluate whether a projector-space warp should happen as a final compositing pass after volumetric rendering, rather than inside each visual mode.

## Deferred: Spark 2.2.x

Source: https://github.com/sparkjsdev/spark

Spark is MIT-licensed and actively maintained; it had distribution/CI updates on 2026-09-21. It provides a Three.js Gaussian-splat renderer with multiple splat formats, multiple viewpoints, dynamic splat transforms, real-time color/displacement/skeletal animation, and a shader graph.

Why deferred: this week's changes were packaging/typecheck maintenance rather than a new rendering capability, and a direct integration would introduce a JavaScript/Three.js runtime beside the existing Python/ModernGL stack. The dynamic-splat shader graph remains worth revisiting if M6 moves toward authored volumetric performers or browser-based remote previews.

## Watched but not counted as new this week

- WebSplatter (MIT): compelling cross-device WebGPU 3DGS architecture with wait-free radix sorting and broad device testing, but its public 1.0.0 archive predates this sweep window. Keep it as a WebGPU architecture reference rather than presenting it as a weekly discovery.
- Ghost Arcade: highly relevant projection/VJ feature set, but the public source history inspected for this sweep did not show a qualifying new source update in the window. Its AGPL licensing also makes code-level reuse a deliberate legal/architecture decision; use it as product/UX reference unless that decision is made explicitly.
