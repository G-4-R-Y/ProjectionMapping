## Implemented on research branch: projector-space polygon mattes

Motivation: the MIT-licensed [Projection Mapper](https://github.com/atul016/projection-mapper) added traced surface outlines and holes in its **2026-11-07** [merge](https://github.com/atul016/projection-mapper/commit/879de56ef840); our own Room Skin had no equivalent surface mask.

Independent, smaller native implementation (no upstream source/assets copied, no dependency added beyond Room Skin's existing OpenCV):
- `src/projection_mapping/surface_masks.py` loads a bounded, validated JSON shape in normalized **projector-output** coordinates, rasterizes 1–16 outlines with even–odd parity for holes, and optionally adds **inside-only** feathering (0–256 px). The matte is computed **once**; frame compositing is isolated.
- `experiments/09_room_skin.py`: opt-in `--surface-mask` and `--surface-feather-px`, applied **after** resizing the image to projector output size. Empty flag keeps existing behavior.
- `configs/features.toml`: feature parameters in Room Skin's console; `configs/surface_shapes/demo_arch.json`: reproducible arched-window sample.
- `tests/test_surface_masks.py`: 10 checks for polygons/holes/black floor, inward feather, invalid inputs, shape compatibility.
- `docs/SURFACE_MASKS.md`, Room Skin feature track and roadmap updated.

**Test evidence:** isolated module smoke `PYTHONPATH=src pytest -q tests/test_surface_masks.py` → **10 passed** on test host NumPy 2.3.5/OpenCV 4.13.0/Python; **not** the project's pinned NumPy 1.26 / OpenCV <4.12 environment. Whole-app registry smoke, project suite, actual webcam, GPU, projector, contour alignment, frame-time and Windows bundle remain unvalidated. Never infer projector safety from polygon algebra. Manual trace JSON is **not** camera-to-projector registration, occlusion, compensation or a graphical polygon editor.
